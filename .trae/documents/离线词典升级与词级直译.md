# 离线词典升级 + 词级直译（本轮不做在线）

## Context（为什么做）

现在单词页只有 **2 万条**词库、**精确匹配 + 前缀联想**两种查法：查 `running` 不命中、查 `give up` 不命中、拼错一个字母就白查；阅读器里也不能查词。用户要求「更智能的翻译/查词」，并已拍板：

* **只做离线**（不接在线翻译 API）

* 词库规模：**大而全，\~15 万条**

* 释义里超出字库的字：**补字进** **`font/hanzi.txt`** **并重烘字体**

* 中文反查**本轮不做**（屏幕键盘只有 ASCII）

* **允许破坏词库格式与** **`srv_dict`** **接口兼容性**

目标：查词支持**词形还原、词组、拼写容错、考纲徽章**，并新增**词级直译**（英文句子 → 逐词中文，词形还原后查词、未命中保留原样）。

已实测的关键数字（本方案直接采用）：

| 项      | 数字                                                       |
| ------ | -------------------------------------------------------- |
| 选词结果   | **153041 条**（约 11–12MB 文本，82 字节/行）                       |
| 新增变形行  | 仅 **931** 行（多数变形词本来就是独立词条）；**56398** 行带 `lemma` 原形提示     |
| 稀疏索引   | 每 64 条一个锚点 = 2392 项 × 12B = **28KB**（PSRAM 常驻）           |
| 一次精确查  | 顺序读 2.6–5.2KB → **3–8ms**（SD 按 1MB/s 估）                  |
| 容错扫描   | 同「前两字母」桶内扫，硬上限 64KB → 典型 <10ms、最坏 \~65ms                 |
| 缺字     | **124 个**（新词库用到、hanzi.txt 没有）；已用 fontTools 确认源字体**全部覆盖** |
| 字体重烘增量 | **+\~15KB flash**（125 字形 4bpp）                           |

## 1. 数据格式（新，SD 卡上）

### 1.1 `<SD>/dict/dict.dat` —— 过滤后的主表

UTF-8 无 BOM、LF 行尾，**每行 5 字段 / 4 个 TAB**：

```
word <TAB> phonetic <TAB> definition <TAB> flags <TAB> lemma
```

* `word`：小写，匹配 `^[a-z][a-z'\- ]*$`（允许 `give up` 这类短语）；首字符必为 `a-z`

* `phonetic`：IPA，可空（沿用现有音标白名单清洗）

* `definition`：`n. 义项；义项；v. 义项`，**生成期保证不含 TAB/CR/LF**（换行转 `；`、制表符转空格）；只允许 hanzi.txt 汉字 + 中文标点 + 数字/连字符 + `…`

* `flags`：紧凑徽章码，单字符一标签：`4`=CET4、`6`=CET6、`K`=考研、`G`=高考、`Z`=中考、`T`=TOEFL、`I`=IELTS、`R`=GRE、`O`=Oxford3000、`C<1-5>`=Collins 星级

* `lemma`：本词的原形（可空），非空时必须是表内某个 `word`

* **排序**：按 `word` 的 UTF-8 字节序升序（纯 ASCII 下等价于 `strcasecmp`，设备端直接 `strcasecmp` 比对）

* 行长上限：生成期把 `definition` 截到 \~420 字节 + `…`，设备端缓冲 640

### 1.2 `<SD>/dict/dict.idx` —— 稀疏索引

```
头 24B: magic "DCTX" | ver u16 | step u16(=64) | count u32 | main_size u32 | 保留 8
锚点 12B/项 × 2392: u32 file_offset(小端) | char key[8]（块首词前 8 字节，'\0' 补齐）
```

锚点里带**块首词的 8 字节前缀**，所以二分定位完全在内存里完成、零 SD 读；定位到块后一次顺序读 ≤64 行。设备端再据此推导 **676 项两字母桶表**（`u16 first_anchor, end_anchor`，5.4KB），供容错扫描限定范围。常驻合计 ≈34KB。

### 1.3 词形变体：**作独立行插进主表**（不单开 lemma 表）

* 变形词若本来就是独立词条（`running`/`runs`）→ **保留原词条**，只按 `exchange` 的 `0:` 关系回填 `lemma=run`（详情页显示「running → run」，点它跳过去）

* 变形词不在表内 → 追加一行：`form <TAB> <base音标> <TAB> <base释义> <TAB> <空> <TAB> <base>`（实测仅 931 行）

好处：查找路径只有「查主表」一条，前缀联想天然带出变形词，不需要第二个文件与二段查找。

## 2. `srv_dict` 重写（`main/services/srv_dict.h/.c`）

```c
typedef struct {
    char     word[40];
    char     phonetic[48];
    char     lemma[40];     /* 原形；空 = 无 */
    char     def[512];
    uint16_t tags;          /* SRV_DICT_TAG_CET4/…/OXFORD 位或 */
    uint8_t  collins;       /* 0~5 */
} srv_dict_entry_t;

esp_err_t srv_dict_init(void);      /* 同步：开 .dat + 读 28KB 索引 ≈30ms；幂等 */
void      srv_dict_reload(void);    /* SD 重挂后重读 */
bool      srv_dict_ready(void);
esp_err_t srv_dict_lookup(const char *word, srv_dict_entry_t *out);
esp_err_t srv_dict_lookup_lemma(const char *word, srv_dict_entry_t *out);  /* 词形还原 */
int       srv_dict_prefix(const char *prefix, cb, arg, max);
int       srv_dict_suggest(const char *word, cb, arg, max);                /* 拼写容错 */
void      srv_dict_translate(const char *text, srv_dict_word_cb_t cb, void *arg);
```

实现要点：

* **删掉** `srv_dict_init_async / srv_dict_busy / srv_dict_index_ready`（新索引 28KB，同步就绪；旧版要扫 MB 级文件才需要后台建索引）

* `exact()`：小写化 → 在锚点表上二分 → `fseek` → 顺序扫 ≤64 行 `strcasecmp`

* `lookup_lemma()`：先 `exact`；未命中再按规则还原（`-s/-es/-ed/-ing/-ly/-er/-est`、辅音双写、`-ies→-y`）重查 ≤2 次

* `suggest()`：用两字母桶表限定范围，扫行做「长度差 ≤2 且编辑距离 ≤1」，**累计读满 64KB 即放弃**

* `translate()`：`[^A-Za-z'-]+` 切 token → 每 token 走 `lookup_lemma` → 命中给 entry、未命中回调 `e=NULL`

* 性能细节：**常开一个** **`FILE*`**（省 fopen 开销）+ **16 条 LRU 缓存**（≈12KB PSRAM，联想点进详情、直译重复词都受益）

* `init` 里校验格式：首行 TAB 数 ≠ 4 → 报「词库格式不对，请用 tools/build\_dict.py 重新生成」，避免误读旧 `dict.csv`

* `srv_dict.c` 在 `sim/CMakeLists.txt` 的 `SRV_REAL` 里已是真代码，**sim 侧无需改 CMake**

## 4. 词库生成流水线：新的 `tools/build_dict.py`

单文件、可分段运行：

```
python tools/build_dict.py                  # 全流程：选词→生成→索引→拷 sim→报告
python tools/build_dict.py --only-data      # 只出 dict.dat/dict.idx
python tools/build_dict.py --update-hanzi   # 把缺字追加进 font/hanzi.txt
python tools/build_dict.py --limit N        # 小样本调试
```

1. **选词**（流式读 `words/ecdict.csv`，66MB）：`translation` 非空 且 `word` 匹配 `^[a-z][a-z'\- ]*$` 且满足
   `tag非空 ∪ collins>0 ∪ oxford>0 ∪ bnc>0 ∪ frq>0 ∪ exchange非空` **或** `(纯字母 且 有音标 且 len<=7)`
   → 实测 **153041 条**（旋钮：`EXTRA_MAX_LEN` 7→6 约 14 万，7→8 约 16.8 万）
2. **释义清洗**：复用 `tools/_step5_generate.py` 里的 `clean_def / split_items / norm_pos / merge_defs / clean_phon_*`（搬到新脚本）；`_manual_defs.py` 的 **786 条 MANUAL 最高优先**、`5 条 REMOVE` 继续生效；每词性 ≤5 义项。**改动：`clean_def`** **不再丢字库外汉字**，改为「保留 + 统计缺字」
3. **flags**：由 `tag`/`collins` 映射成徽章码
4. **变体展开**：解析 `exchange` 回填 `lemma` / 追加变形行（规则见 1.3），生成期断言 `lemma` 目标存在
5. **去重排序** → 按字节序写 `dict.dat`
6. **索引**：step=64 写 `dict.idx`（断言每个 offset 落在行首）
7. **缺字报告 + 补字**：`--update-hanzi` 把缺字追加进 `font/hanzi.txt`（实测 124 个）
8. **双写**：`dict/dict.dat`、`dict/dict.idx` → `shutil.copy2` 到 `sim/sd/dict/`；**旧** **`dict.csv`** **改名** **`dict.csv.bak`**（便于回滚；设备端只认 `.dat`）
9. **报告**：条数/字节数/最长行/flags 分布/缺字数/新增变形行数/锚点数 → `tools/build_report.txt`

旧脚本处置：`_step1/_step1b/_step2/_step3/_step4` 废弃（依赖的文件已不在），`_step5_generate.py` 作为**函数来源**保留到新脚本跑通；`check_dict.py` 改写为新格式校验器（5 字段/4 TAB/排序/无重复/音标白名单/**释义汉字全在 hanzi.txt**/行长）；`tools/_*.py|txt|json` 与 `_m*.py` 等 \~90 个临时文件**在阶段 1 验证通过后再删**，`_manual_defs.py` 永久保留。

## 8. 风险与注意

* **ECDICT 授权**：MIT，个人自用没问题；若将来随固件分发词库，需保留其授权署名

* 释义里的繁体/生僻字（124 个）靠补字解决；**不做繁→简转换**（不装 opencc）

* 短语来自 ecdict 的 894 条多词条目 + 已有候选；不额外枚举造短语，避免混进垃圾

* 主表 11–12MB 会随 SD 卡一起走；`dict.idx` 与主表**必须同批更新**（生成期保证，改动后重新拷卡）

* 不引入新 python 包（opencc / pypinyin 都不装）；只用 PIL / fontTools / lv\_font\_conv（已就位）
